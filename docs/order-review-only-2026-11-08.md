# `/order` = صفحة مراجعة الطلب فقط — 8 نوفمبر 2026

> المطلوب (من صاحب الموقع): «صفحة مراجعة الطلب `/order` دي يكون فيها فقط الطلبات
> اللي تم اختيارها من الكاتالوج بس بحيث أحدد كميتها ثم نأكد الأوردر.»
>
> قبل التغيير: `/order` كانت تجربة موجّهة فيها **مرحلة تصفح للكتالوج كله**
> (`browse → review → contact → success`) — نفس الـ ٦٩ صنفًا، بحث، فلاتر فئات،
> وشريط عائم قبل ما توصل للمراجعة. يعني الصفحة كانت بتعرض الكتالوج تاني،
> مش اختيارات العميل بس.

## اللي اتغيّر

| قبل | بعد |
| --- | --- |
| `browse` (كتالوج كامل + بحث + فلاتر) ← `review` ← `contact` ← `success` | **`review` ← `contact` (تأكيد)** ← `success` |
| الأصناف تظهر في المراجعة بعد خطوة تصفح كاملة | الصفحة **بتفتح على أصناف الطلب مباشرة** |
| شريط «راجع الطلب» عائم في صفحة `/order` نفسها | اتشال — مفيش تصفح هنا أصلاً |
| الكمية كرقم نصّي في حقل صغير بجانب الاسم | صف كامل لكل صنف: صورة + وحدة بيع + حقل كمية (−/+) + كميات سريعة + ملاحظة + حذف |
| مفيش ملخص كميات | ملخص جانبي **بإجمالي كل وحدة قياس** + عدّاد أصناف |
| بيانات التواصل منفصلة عن ملخص الطلب | خطوة التأكيد فيها نموذج التواصل **ومراجعة نهائية لكل صنف بكميته** |

## الفلو

```
/catalog (الخطوة ١)                       /order (الخطوة ٢ — المراجعة)
─────────────────────                     ────────────────────────────────
الـ ٦٩ صنفًا + بحث + فلاتر               01 مراجعة الكميات
زر «أضف للطلب» على كل بطاقة   ───────►     • الأصناف المختارة فقط (مفيش كتالوج)
  ↳ { selected:true, qty:'' }              • كمية إلزامية لكل صنف
شريط عائم «راجع الطلب»                    • كميات سريعة (−/+) + ملاحظة + حذف
                                          • ملخص: إجمالي كل وحدة
                                          02 تأكيد الطلب
                                            • الاسم والهاتف (مطلوبين)
                                            • قائمة نهائية: صنف + كمية + وحدة
                                            • «تأكيد وإرسال الطلب» → /api/order
```

## التفاصيل

- **مصدر الأصناف**: `readDraft()` من `app/catalog/draft.ts` على مفتاح
  `nilebed-order-v1`. الصفحة بترتّب الأصناف بترتيب الكتالوج وبتستبعد أي ID مش
  موجود (`validIds`). تزامن بين التابات عبر حدث `storage`.
- **حالة فاضية**: لو مفيش أي اختيار تظهر رسالة «لسه ما اخترتش أي أصناف» + زر
  «افتح الكتالوج واختار أصناف» — بدل ما كان المستخدم يشوف كتالوج كامل.
- **التحقق من الكمية**: `continueToContact()` و`submit()` بيرفضوا لو أي صنف
  بلا كمية: `missingIds` بتميّز السطر (إطار أحمر + رسالة + `aria-invalid`)،
  وبتحط التركيز على أول خانة ناقصة.
- **قواعد الكمية** زي ما هي: أرقام عربية (٠١٢٣) بتتحوّل لاتيني، الفاصلة العشرية
  مقبولة، وحدات القطع بتتقرّب لعدد صحيح، سقف ٩٩٩٩٩٩، وحدات الكيلو (٠٫٥) والم³
  (٠٫١) بتقبل كسور.
- **الكميات السريعة**: أزرار مقترحة حسب الوحدة (رول ١/٥/١٠، كجم ١٠/٥٠/١٠٠…)
  بتظهر لما الخانة فاضية، وبتختفي بعد ما تتحدد الكمية.
- **الملخص**: إجمالي كل وحدة قياس (`unitTotals`) + عدّاد «N أصناف / N وحدات قياس»،
  وسطر صريح إنه **مفيش أسعار أو مبالغ** في الصفحة.
- **خطوة التأكيد**: نموذج التواصل (الاسم والهاتف مطلوبين) + قائمة نهائية
  للقراءة فقط (صنف + ملاحظة + كمية + وحدة) + زر «تأكيد وإرسال الطلب».
- **بعد الإرسال**: شاشة نجاح برقم المرجع، والمسودة بتتفضّى (أصناف + مرجع جديد)
  فمفيش طلب مكرر لو رجع للصفحة.
- **الروابط القديمة**: `/order?add=<item-id>` لسه شغال — بيسجّل الصنف بكمية فاضية
  ثم بيشيل الباراميتر من العنوان (`history.replaceState`) عشان إعادة التحميل
  ما تضيفهوش مرتين.
- **الوصف/العنوان**: `app/order/layout.tsx` بقى «مراجعة الطلب وتحديد الكميات».
- **ألوان**: `app/order/order.css` اتكتب من جديد على توكنز `styles/tokens.css`
  بالكامل (صفر ألوان حرفية، صفر تعديل على البالِت)، و`styles/contrast.css`
  اتحدّث عشان يثبّت `--nb-on-hot` على الأزرار المصمتة الجديدة
  (`.or-primary`, `.or-qty button:hover`, `.or-progress-step.is-active > span`)
  وشارة النجاح.

## التحقق

- `npm run typecheck` ✅ · `npm run check:contrast` ✅ (٤٦ زوجًا في البالِتين) ·
  `npm run build` ✅ (`/order` static) · `git diff --check` ✅.
- **اختبار سلوكي فعلي** (React DOM mount للصفحة على مسودة فيها ٤ أصناف):
  - بتعرض ٤ سطور بس، وأي صنف مش في المسودة مش موجود، ومفيش أي واجهة تصفح للكتالوج.
  - «تأكيد الكميات» بيتمنع وبيعلم السطر الناقص، والكمية السريعة بتملاه.
  - «٤» عربي → 4، و«7.6 رول» → 8 (وحدة عدد صحيح)، وإجمالي الملخص صح لكل وحدة.
  - الاسم/الهاتف مطلوبين، وبعدهم `POST /api/order` واحد فيه ٣ سطور بالأرقام
    الصحيحة + رقم المرجع، وبعدها شاشة النجاح والمسودة بتتفضّى.
  - السويتش للإنجليزي بيقلب `dir` لـ `ltr` والنصوص بتتغيّر.
- `/api/order` من غير `ORDER_WEBHOOK_URL` بيرجّع `fallback` (الواتساب/البريد)
  زي ما هو — الـ payload والـ fallback ما اتغيّروش.

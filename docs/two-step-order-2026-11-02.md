## المطلوب (كما ورد)

1. «راجع الطلب» تبقى **فلوتنج في الشاشة**، مش في آخر الصفحة تحت خالص.
2. اللي أضيفه من الكتالوج **يُضاف فقط**، وما يروحش تلقائي لتحديد الكمية.
3. الكتالوج هو مكان **الاختيار الأولي**؛ الكميات في الخطوة الجاية.
4. يتكتب صراحة في الكتالوج إن ده «اختيار أولي» وإن الكميات في الخطوة الجاية.
5. صفحة تحديد الكميات تعرض **الأصناف اللي اختارها المستخدم فقط**، مش الكتالوج كله.
6. سيستم توكنز واحد + بالِت لايت/دارك + سويتش كامل بلا مشاكل كونتراست
   → موثّق في `docs/design-tokens-2026-11-02.md`.

## الفلو النهائي

```
الخطوة ١  /catalog                         الخطوة ٢  /order
──────────────────────────────────────    ────────────────────────────────────────────
استعراض الـ ٦٩ صنفًا                     تجربة موجّهة: browse ← review ← contact ← success
زر «أضف للطلب» على كل بطاقة           →   browse: شريط عائم «راجع الطلب» + عدّاد الاختيارات
   ↳ يسجّل { selected:true, qty:'' }       review: **الأصناف المختارة فقط** + حقل كمية لكل صنف
   ↳ لا تنقّل، لا كمية تلقائية             ↳ الكمية إلزامية قبل المتابعة، حذف/ملاحظة متاحة
شريط «راجع الطلب» عائم دائمًا            contact/success: بيانات التواصل + الإرسال
```

### ١. الشريط العائم

- **`/catalog`**: يظهر **دائمًا** (حتى لو العدّاد صفر)، `position: fixed` في أسفل
  الشاشة: حقيبة + «طلبك الحالي N صنف» + سطر «اختيار أولي — الكميات بتتحدد في
  الخطوة الجاية» + زر برتقالي «راجع الطلب» بسهم حسب RTL/LTR. الشكل مقتبس من
  الصورة المرجعية اللي بعتها صاحب الطلب. مُرندَر **كأخ لـ `<main>`** (مش جواه)
  فمفيش `overflow`/`clip` يقدر يحبسه؛ `z-index: 900`، و`padding-bottom` على
  الصفحة عشان ما يغطّيش الفوتر.
- **`/order`**: تجربة PR #12/#13 ليها شريطها العائم الخاص
  (`.or-floating-cart`) في خطوة التصفح، بنفس المعنى: عدّاد + زر «راجع الطلب»
  بيودّي لخطوة المراجعة. الاتنين بيستخدموا نفس التوكنات ونفس أزواج الكونتراست.
- نسخة موبايل مضغوطة، و`prefers-reduced-motion` يلغي الأنيميشن.

### ٢. الاختيار الأولي فقط

- `app/catalog/draft.ts` هو **مصدر الحقيقة المشترك**: `readDraft` / `writeDraft` /
  `togglePicked` / `pickWithoutQuantity` على مفتاح `localStorage`
  `nilebed-order-v1`. الصفحتان تقرآن وتكتبان نفس المسودة، مع مزامنة بين التابز
  عبر حدث `storage`.
- كل سطر بيتكتب بالشكل `{ selected: true, qty: '', note: '' }`. حقل `selected`
  مهم: صفحة `/order` المُعاد بناؤها بتسترجع السطر بشرط
  `line.selected || qty > 0`، فبدونه كان الاختيار هيضيع عند فتح الصفحة.
- زر البطاقة بقى `<button aria-pressed>` مش رابط `/order?add=...`. الضغطة تضيف
  سطرًا **بكمية فارغة** أو تشيله؛ **لا** `window.location`، **لا**
  `scrollIntoView`، **لا** قيمة `1` افتراضية.
- النسخة القديمة `?add=<id>` لسه مقبولة للتوافق مع الروابط المحفوظة، لكنها
  بتسجّل الصنف بكمية فارغة فقط (بدون تحديد كمية/سكرول). `?unit=<id>` لسه فلتر.
- نص صريح في الكتالوج: تنبيه «**اختيار أولي**: الزرار بيضيف الصنف لقائمة طلبك
  من غير ما يحدد كمية أو ينقلك لصفحة تانية…» + تعديل `unitsNote` + مؤشر
  «١ الاختيار الأولي ← ٢ مراجعة الطلب وتحديد الكميات» + سطر داخل الشريط العائم،
  بالعربي والإنجليزي. كمان نسخ `/order` فيها `preselected` / `quantityNext`.

### ٣. صفحة المراجعة = المختارة فقط

- `/order` (نسخة PR #12/#13) بتحسب `selected = items.filter(i => order[i.id]?.selected)`
  وبترندر **الاختيارات فقط** في خطوة المراجعة؛ مفيش عرض للكتالوج كله في المراجعة.
- الكمية إلزامية لكل صنف مختار: `continueToContact` و`submit` يمنعوا المتابعة لو
  أي صنف لسه بلا كمية، مع رسالة `quantityError` واضحة.
- قواعد الكمية زي ما هي: أعداد صحيحة للقطع، ٠٫٥ للكجم، ٠٫١ للم³، الأرقام
  العربية، الحد الأقصى ٩٩٩٩٩٩؛ الرقم المرجعي `NB-YYYYMMDD-XXXX`؛ الاسم/الهاتف
  مطلوبان؛ `POST /api/order` + `ORDER_WEBHOOK_URL` الاختياري + `fallback` لواتساب/
  البريد؛ الحفظ في `localStorage` فقط، بلا قاعدة بيانات وبلا أسعار.
- التسميات والـ metadata والروابط من الرئيسية بقت «راجع الطلب / مراجعة الطلب
  وتحديد الكميات» بدل «كوّن طلبك / Build an order».

### ٤. توحيد نظام التوكنز بعد اندماج PR #13

- `styles/tokens.css` هو **مصدر الحقيقة الوحيد**: ٦٨ بدائية لايت + ٦٨ بدائية دارك
  + ٨٨ توكنًا دلاليًا، وسويتش واحد `html[data-theme='dark']` بيعيد تعيين الـ ٦٨
  دورًا المعتمدين على البالِت (مفيش أي دور ناقص).
- أسماء الأدوار اللي جابت PR #13 (`--nb-brand`, `--nb-ink-muted`, `--nb-line`,
  `--nb-surface-raised`, …) اتحوّلت لـ **أسماء مستعارة** جوه نفس الملف، فصفحة
  `/order` الجديدة تشتغل على نفس البالِت بالظبط. ملف `styles/design-tokens.css`
  اتشال بعد نقل كل محتواه (الأدوار + المسافات + أنصاف الأقطار + الخطوط) لـ
  `styles/tokens.css` — مفيش ملفّي توكنز ولا سويتشين.
- `app/order/order.css` بالكامل اتحوّل من ألوان حرفية لـ `var(--nb-*)` (١٦٥
  استبدالًا)، و`styles/contrast.css` بيثبّت `--nb-on-hot` على الأزرار الكورالية
  المصمتة في `/order` في البالِتين.
- **ما اتغيّرش من `main`**: كود صفحة `/order`، مراحلها، شريطها العائم، نسخها،
  والـ metadata بتاعتها. التغيير عليها هو التوكينيزيشن + أزواج الكونتراست بس.
